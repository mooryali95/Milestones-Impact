# ملفات الإصدارات السابقة

تصور تحديث المنصة بلا أثر على المستخدمين، المرحلة 5 البند 6 (الخيار أ)، وشرط ش2: تبويب فُتح قبل النشر يستطيع فتح كل الأقسام الكسولة 14 يومًا على الأقل.

- `leaders/` و`admin/`: لكل تطبيق مجلد `assets/` بنسخ الملفات التي قدّمها الإصدار المرقّى ولم يعد البناء الحالي ينتجها، و`retained.json` قائمتها الصريحة بتاريخ دخول كل ملف (`YYYY-MM-DD`).
- لا يكتب هنا إلا `node scripts/ops/retain-assets.mjs update`، من فرع `release` (الإصدار الذي تبني منه Cloudflare Pages). وما مضى عليه أكثر من 14 يومًا يُحذف، إلا ما يقدّمه الإصدار المرقّى الآن. وتاريخ ملف بناه الإصدار المرقّى نفسه يتجدد مع كل تحديث ما دام يقدّمه، فيُعدّ من آخر تحديث قبل الترقية لا من أول تحديث في الطلب.
- البناء (`npm run leaders:build` و`npm run admin:build`) ينسخ المحتوى إلى `leaders/assets/` و`admin/assets/` كما يُنسخ `public/` (`shared/build/release-files.mjs`). فالناتج دالة في المودع وحده، وفحص «المبني المودع يطابق مصدره» يبقى صارمًا.

## متى يُشغَّل

في كل طلب دمج يعيد بناء `leaders/` أو `admin/`، بعد البناء وقبل الإيداع:

```
npm ci && npm run leaders:build && npm run admin:build
node scripts/ops/retain-assets.mjs update
```

الأمر الثاني يقرأ ما بناه المصدر من قائمة يكتبها البناء خارج الناتج (`node_modules/.cache/mi-release-files/`)، فيرفض إن لم يُبنَ التطبيقان أو تغيّر الناتج بعد البناء. ومن يُدمج ثانيًا يعيد الأمرين بعد دمج `main` في فرعه: الإصدار المرقّى قد تغيّر. الفحص `node scripts/ops/retain-assets.mjs check` في CI (وظيفة web، ثم وظيفة deploy قبل أي نشر) يرفض ناتجًا يُسقط ملفًا يقدّمه الإصدار المرقّى. وتعارض `retained.json` بين طلبين يُحل بإعادة الأمرين، لا باليد.

`node scripts/ops/retain-assets.mjs size` يطبع حجم المجلد.
