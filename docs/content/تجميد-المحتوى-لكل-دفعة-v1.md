# تجميد المحتوى لكل دفعة v1

**التاريخ:** 2026-11-07 · **القرار:** D02 في `docs/journey/2026-11-07-سجل-قرارات-لجنة-الخبراء-v1.md` · **الحالة:** الآلية مبنية (الحزمة 7)، وقطع إصدار الدفعة الأولى في الحزمة 12 بيد المالك

كل دفعة تُثبَّت عند بدئها على إصدار محتوى مؤرخ ببصمة sha256، وأي تعديل بعده إصدار جديد لا يمس الدفعة الجارية. الاستثناء الوحيد تصويب حرج بتوقيعين.

## 1. ما يشمله الإصدار

بيان واحد (`supabase/content/releases/<id>/MANIFEST.json`) ببصمة لكل عنصر وبصمة لكل منطقة وبصمة كلية:

| المنطقة | المصدر | مفتاح العنصر |
|---|---|---|
| أبواب الكتيب واختباراتها | `handbook_modules` على الإنتاج | `البعد/مفتاح الباب`، ومعه بصمة الاختبار وحده |
| بنك الأسئلة وأدواته | `questions` و`instruments` | `الأداة/الرمز` |
| المختبر | `lab_items` | مفتاح الأداة |
| النماذج | `learning_models` | مفتاح النموذج |
| معيار التسكين وإعداد الأثر | `placement_model` | صف واحد |
| إعداد التقييم الختامي | `programs.final_eval` | معرّف البرنامج |
| السلّم الرباعي | `RUBRIC_SCALE` في `labels.js` | إصداره |
| سجل المفاهيم | `supabase/content/concepts/registry.json` | الملف |
| السياسة | `policy-digest.js` | نسختها |

## 2. ما يُقفل وما يُسجَّل

- **إصدار الدفعة:** `cohorts.content_release`، لا يتغير بعد تثبيته إلا بترحيل ترقيع.
- **اختبار الباب:** لا يتغير بعد أول نتيجة فيه، لأي كاتب (اللوحة أو ترحيل إصدار كتيب جديد). ترحيل يحاول ذلك يفشل كاملًا برسالة تسمي الباب.
- **مواصفة أداة المختبر:** لا تتغير بعد أول محاولة منتهية.
- **مع كل نتيجة باب:** إصدار الدفعة، وبصمة الاختبار، والإجابات نصًا (السؤال والخيار المختار) لتصويب عادل. **مع كل محاولة مختبر:** إصدار الدفعة. **في الشهادة:** إصدار المحتوى في لقطتها.
- **بند قراءة الكتيب:** يُحسب على أبواب إصدار الدفعة، فلا يتغير مطلوبه بباب يُضاف أثناءها.
- **العرض:** إصدار المحتوى في ملف المشارك للمستشار، وفي ملفه في اللوحة.
- **سجل الإصدارات والتصويبات:** لا يُعدَّل ولا يُحذف (ترحيل `20261107180000`، متسامح).

كاتون مخفي وخارج التقييم (D17)، فلا يحمل إصدارًا الآن، ويُضاف عمود إصداره عند تفعيله.

## 3. قطع إصدار الدفعة (الحزمة 12)

بعد مراجعة الخبراء والمصالحة (D01) وقرارَي D11 وD12، وقبل أول قياس مبدئي:

1. تصدير الإنتاج قراءةً: `SUPABASE_ACCESS_TOKEN=... node scripts/content/export-live.mjs --check`، ويجب ألا يبقى فرق غير مُصالح.
2. توليد البيان والترحيل بتوقيعين:

```bash
node scripts/content/release.mjs --from=.content-live/<التاريخ>/live.json --id=2026.11-c1 --cohort=<معرّف الدفعة> --signed-by=<المالك>,<رئيس لجنة المحتوى> --git=<الإيداع>
```

3. مراجعة البيان في طلب دمج، ثم الدمج، ثم وسم المستودع:

```bash
git tag content-2026.11-c1 <إيداع الدمج>
```

4. تطبيق ترحيل الإصدار (مؤجل بقرار D02) عبر سير عمل الترحيل.

## 4. التصويب الحرج

لمفتاح خاطئ، أو خطأ علمي أو نظامي أو لغوي فادح، في اختبار باب بعد التثبيت:

```bash
node scripts/content/patch.mjs --base=2026.11-c1 --key=<البعد/مفتاح الباب> --quiz-file=<الاختبار المصوَّب> --reason="<السبب>" --signed-by=<موقّع1>,<موقّع2> --regrade=rekey
```

- يكتب إصدارًا ترقيعيًا (`2026.11-c1.1`) وترحيلًا يحدّث الاختبار بعد التحقق من بصمته في الإصدار الأساس، ويسجل التصويب بتوقيعيه وسببه، وينقل الدفعات المثبتة إلى الإصدار الترقيعي، ويضع إشعارًا لمن أجاب الاختبار في طابور البريد.
- **إعادة التصحيح:** `rekey` بالمفتاح الجديد، و`drop` بإسقاط ما حُذف من الأسئلة. تُرفع النتيجة إن علت نسبتها وحدها، فلا ينقص أحد بأثر رجعي. ومن لم تُحفظ إجاباته (قبل هذه الحزمة) تبقى نتيجته. النقاط الممنوحة لا يُعاد حسابها.
- بعده يُحدَّث أصل الباب في المستودع بإصدار الكتيب التالي بالنص نفسه، فلا يبقى انحراف.
- تصويب أداة مختبر أو سؤال في البنك يتبع المسار نفسه بترحيل يكتبه المنفذ يدويًا بالحارس والسجل والتوقيعين، حتى يُضاف له مولّد.

## 5. ما بقي

- قطع إصدار الدفعة الأولى وتثبيته (الحزمة 12، بيد المالك).
- اللقطة متعددة الإصدارات لدفعتين متوازيتين على محتويين مختلفين: قبل أي دفعة ثانية.
