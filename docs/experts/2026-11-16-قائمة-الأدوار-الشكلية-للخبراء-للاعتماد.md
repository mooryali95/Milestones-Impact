>
> **المصدر:** الكود على `main` (`f67c2c6f`، بعد دمج #382 و#384). لم يُستعلم الإنتاج، ولا بذرة خبراء في المستودع. ولا أسماء ولا عناوين بريد في هذه الوثيقة: التصنيف على مستوى الدور، وقاعدة على مستوى الشخص تطبقها الإدارة.

## 1. ما المقصود بالدور الشكلي

قبل #370 كان الاعتماد يشترط دورًا في الرحلة، فمن أُريد له أن يقرأ الكتاب الأم وحده (عضو لجنة محتوى أو قياس) أُعطي دورًا لا يمارسه ليمر الاعتماد. هذا الدور يدخله في المطابقة و«اختر خبيرك» والعرض التلقائي على المشاركين. وبعد #370 صار الاعتماد يقبل عضوية اللجنة وحدها، فبقي التنظيف.

والدور الشكلي يظهر على مستويين:

- **على مستوى الدور:** دور في القائمة لا وظيفة له في الرحلة، فكل من يحمله يحمله شكلًا.
- **على مستوى الشخص:** دور له وظيفة، لكن صاحبه لم يمارسه قط وهو عضو لجنة.

## 3. التصنيف المقترح للاعتماد

| الدور | التصنيف | السبب |
|---|---|---|
| موجّه (`coach`) | **يبقى** | وظيفة كاملة: طلب، ومطابقة، وجلسات توجيه مربوطة به |
| مستشار (`advisor`) | **يبقى** | أوسع الأدوار وظيفة: الدفعة والمجموعة والجاهزية والملف ووثيقة المبادرة |
| مرشد (`mentor`) | **يبقى** | صار له منذ #382 عمل لا يؤديه غيره: متابعة مستمرة وتذكير باسمه. ويُوضَّح الفرق مع الموجّه في الوصف: الموجّه جلسات فردية بموعد، والمرشد متابعة مستمرة طوال الرحلة |
| خبير موضوعي (`specialist`) | **يبقى، ويُصحَّح وصفه** | وظيفته الفعلية استشارة في المنهج والأدوات. والوصف يعد بـ«ورش وجلسات تخصصية» غير مبنية، فيصير «استشارة في المنهج والأدوات في بُعد» حتى يُبنى ربط الخبير بالجلسات بقرار مستقل |
| مقيّم (`assessor`) | **يُدمج في المستشار** | لا وظيفة له في الرحلة. وما يعد به وصفه (تقييم المبادرة) يؤديه المستشار فعلًا (مراجعة وثيقة المبادرة)، والاعتماد الختامي للإدارة. وهو أرجح دور أُعطي شكلًا لعضو لجنة. والدمج أسلم من الحذف: لا يُكسر سجل قائم، ومن يحمله ويؤدي عملًا يُنقل إلى المستشار |

**كيف يُنفَّذ دمج «مقيّم» بعد الاعتماد (بلا كسر):**

1. يُخفى من خيارات الدعوة والانضمام العام والإسناد اليدوي وإضافة فريق الدفعة، ويُصحَّح نص الانضمام العام إلى «موجّهًا ومستشارًا ومرشدًا».
2. يبقى في `EXPERT_ROLES` وفي قيد القاعدة، فيُقرأ أي سجل قديم ويُعرض باسمه، ولا يفشل حفظ قائم.
3. من يحمله يُعالَج بقاعدة الشخص في §4: إن كان عضو لجنة بلا أثر فُرّغ، وإن كان له أثر نُقل إلى «مستشار» بقرار في ملفه، وإن كان خبير رحلة بلا أثر وبلا دور آخر عُرض على المالك.
4. حين لا يبقى أحد يحمله ولا طلب قائم به، يُحذف من القائمة والقيد بترحيل صغير يُقرأ رقمه وقت البناء من `main` والطلبات المفتوحة.

## 4. القاعدة على مستوى الشخص (للمرحلة 2)

**«أثر في الرحلة»** = أي صف للخبير في واحد من: طلبات الخبراء (`expert_requests`)، وجلسات التوجيه (`coaching_sessions.expert_id`)، ومستشار الدفعة (`cohorts.advisor_expert_id`)، وفريق الدفعة (`cohort_experts`)، ومستشار المجموعة (`cohort_groups.advisor_expert_id`)، وإجابات الأقران (`peer_answers.expert_id`).

| الفئة | الوصف | الإجراء المقترح |
|---|---|---|
| أ | عضو لجنة، وله أدوار، ولا أثر له في الرحلة | **تُفرَّغ أدواره** ويبقى عضو لجنة: يخرج من المطابقة ويبقى الكتاب مفتوحًا له |
| ب | عضو لجنة، وله أدوار، وله أثر في الرحلة | **يبقى في الخدمتين** كما هو |
| ج | ليس عضو لجنة، ودوره «مقيّم» وحده، ولا أثر له | **يُعرض على المالك:** يُنقل إلى «مستشار» إن كان يؤدي التقييم فعلًا، أو تُفرَّغ أدواره فيبقى ملفه معتمدًا بلا خدمة |
| د | ليس عضو لجنة، ومعه «مقيّم» مع أدوار أخرى أو له أثر | يُزال «مقيّم» من أدواره، ويُضاف «مستشار» إن كان له أثر بدور مقيّم |
| هـ | عضو لجنة بلا أدوار | لا إجراء: مفصول أصلًا بعد #370 |
| و | خبير رحلة بلا «مقيّم» | لا إجراء |

**الأعداد قبل التنفيذ، بلا أسماء:** يشغّل المالك في Supabase ← SQL Editor هذه الاستعلامات للقراءة وحدها (جُرّبت على البنية المرجعية `supabase/schema/baseline.sql`). تعيد أعدادًا لا أسماء، والأسماء يراها المالك في «الخبراء» وحده ولا تُكتب في المستودع:

```sql
-- عدد الخبراء المعتمدين في كل فئة
with trace as (
  select expert_id as id from leaders.expert_requests where expert_id is not null
  union select expert_id from leaders.coaching_sessions where expert_id is not null
  union select advisor_expert_id from leaders.cohorts where advisor_expert_id is not null
  union select expert_id from leaders.cohort_experts
  union select advisor_expert_id from leaders.cohort_groups where advisor_expert_id is not null
  union select expert_id from leaders.peer_answers where expert_id is not null
)
select case
         when cardinality(e.committees) > 0 and cardinality(e.roles) > 0 and t.id is null then 'أ: لجنة وأدوار بلا أثر في الرحلة'
         when cardinality(e.committees) > 0 and cardinality(e.roles) > 0 then 'ب: لجنة وأدوار وله أثر في الرحلة'
         when cardinality(e.committees) = 0 and e.roles = array['assessor'] and t.id is null then 'ج: «مقيّم» وحده بلا لجنة ولا أثر'
         when cardinality(e.committees) = 0 and 'assessor' = any(e.roles) then 'د: «مقيّم» مع أدوار أخرى أو له أثر'
         when cardinality(e.committees) > 0 then 'هـ: لجنة بلا أدوار (مفصول أصلًا)'
         else 'و: خبير رحلة بلا «مقيّم»'
       end as category,
       count(*) as experts
from leaders.experts e
left join trace t on t.id = e.id
where e.status in ('active', 'paused')
group by 1
order by 1;

-- عدد حاملي كل دور، ومنهم أعضاء اللجان
select r as role, count(*) as experts,
       count(*) filter (where cardinality(e.committees) > 0) as with_committee
from leaders.experts e, unnest(e.roles) as r
where e.status in ('active', 'paused')
group by r
order by r;

-- الطلبات بكل دور: هل مورس الدور فعلًا؟
select role, count(*) as requests,
       count(*) filter (where status = 'accepted') as accepted
from leaders.expert_requests
group by role
order by role;
```

**التنفيذ بعد الاعتماد:** من «الخبراء» في لوحة الإدارة، ملفًا ملفًا: تفريغ الأدوار أو تعديلها بالحفظ الإداري القائم (يقبل تفريغ الأدوار)، فيُسجَّل كل تغيير في سجل التدقيق بالفاعل والوقت. لا تنظيف آلي ولا SQL كتابة. والإرجاع بإعادة الأدوار من سجل التدقيق.

**التحقق بعد التنفيذ:** الاستعلام الأول لا يعيد الفئة أ ولا ج، ومن بقي في المطابقة له أثر أو دور يمارسه. وفي «اطلب استشارة» عند مشارك تجريبي لا يظهر عضو لجنة بلا أثر.
