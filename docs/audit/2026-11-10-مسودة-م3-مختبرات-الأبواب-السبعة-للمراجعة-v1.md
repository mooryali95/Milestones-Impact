# مسودة م3 للجنة المحتوى: مختبرات الأبواب السبعة المفتوحة للتأسيسي (v1)

**التاريخ:** 2026-11-10 · **الحالة:** تصاميم للمراجعة، لا عناصر منفَّذة. لا يُكتب عنصر مختبر في القاعدة قبل اعتماد اللجنة لتصميمه.
**المرجع:** خطة الوصول إلى 90% (v2) §3 م3، وبوابة التقرير «مختبر لكل باب»، ومسودة م3 (v2) §5 التي حددت الأبواب.
**لماذا هذه السبعة أولًا:** هي الأبواب التعليمية المفتوحة للمستوى التأسيسي وبلا مختبر، فتخدم كل مشارك في الدفعة الأولى. الأبواب الأربعة المحجوبة تليها.

## 1. قواعد التصميم

مأخوذة من المختبرات الستة عشر القائمة، حتى يخرج الجديد على نسقها:

- **السياق:** جهة حكومية سعودية أو برنامج من برامج الرؤية، ودور له اسم («مدير مشروع…»، «قائد برنامج…»). لا مانح ولا منظمة دولية.
- **الخطوات:** من الأنواع المستعملة فعلًا في المنصة وحدها: اختيار، تصنيف، مطابقة، ترتيب، وضع على محورين، توزيع. لا نوع جديد يحتاج برمجة.
- **الحجم:** 10 إلى 12 دقيقة و30 إلى 40 نقطة للتأسيسي، بثلاث إلى خمس خطوات.
- **الخاتمة:** جملة تربط التمرين بسؤال الباب، لا تلخيص للدرجة.
- **النوع:** «أداة» حين يطبّق المشارك نموذجًا من الباب، و«موقف» حين يتخذ قرارات متتابعة لها عواقب على مؤشرات.

## 2. التصاميم

### 2.1 المعالم، الباب الأول: خريطة المدارس وما نأخذه منها

| | |
|---|---|
| المفتاح المقترح | `schools-pick-milestone` |
| النوع | أداة |
| العنوان | أي مدرسة تجيب عن سؤالك؟ |
| الدور والموقف | مدير مكتب مشاريع جديد في هيئة حكومية، يسأله رئيسه خمسة أسئلة عن ضبط المشاريع، وعليه أن يعرف أي مرجع يجيب عن كلٍّ منها |
| ما يتمرن عليه | الانتقاء من المدارس بحسب السؤال، لا التعصب لواحدة (مبدأ الباب) |
| الخطوات | 1) مطابقة: خمسة أسئلة عملية مع المرجع الأنسب (PMI، Axelos، P3M3). 2) تصنيف: ست عبارات إلى «مرحلة ذات بوابة» أو «مجال معرفة». 3) اختيار: جهة نضجها متدنٍّ، ما أول ما تبنيه؟ |
| الخاتمة | المدرسة وسيلة. السؤال الذي يواجهك هو الذي يختار المرجع |
| الوقت والنقاط | 10 دقائق، 30 نقطة |

### 2.2 المعالم، الباب الثاني: الإطار المنطقي والمعلم في المشروع الحكومي

| | |
|---|---|
| المفتاح المقترح | `results-chain-sort` |
| النوع | أداة |
| العنوان | سلسلة النتائج: أين يقع كل شيء؟ |
| الدور والموقف | مدير مشروع رقمنة خدمة في وزارة، أمامه اثنتا عشرة عبارة من وثيقة المشروع مخلوطة بين نشاط ومخرج ونتيجة وأثر |
| ما يتمرن عليه | التفريق بين مستويات سلسلة النتائج، وربط المعلم بالنتيجة لا بالنشاط |
| الخطوات | 1) تصنيف: اثنتا عشرة عبارة إلى المستويات الأربعة. 2) ترتيب: خمس حلقات لسلسلة واحدة من المدخل إلى الأثر. 3) اختيار: أي ثلاثة من سبعة أحداث تصلح معالم قرار؟ 4) اختيار: حالة للنقد من الباب، أين الخلل؟ |
| الخاتمة | المعلم في المشروع الحكومي موضع قرار على نتيجة، لا تاريخ انتهاء نشاط |

### 2.3 المعالم، الباب الثالث: حلقة صناعة القرار

| | |
|---|---|
| المفتاح المقترح | `decision-loop-gate` |
| النوع | موقف |
| العنوان | اجتماع المعلم: قرار أم عرض؟ |
| الدور والموقف | مدير مشروع يدخل اجتماع معلم منتصف المشروع أمام لجنة توجيهية. التقرير جاهز، والسؤال: هل يخرج الاجتماع بقرار؟ |
| ما يتمرن عليه | تحويل اجتماع المعلم من عرض إنجاز إلى صناعة قرار، ومعرفة ما يُرفع للهيكل الدائم وما يحسمه الفريق المؤقت |
| المؤشرات | وضوح القرار، وثقة اللجنة، وزخم الفريق |
| الخطوات | 1) اختيار: بمَ تفتتح الاجتماع؟ 2) ترتيب: خطوات حلقة القرار كما في الباب. 3) اختيار: اللجنة تطلب تأجيل القرار، ماذا تفعل؟ 4) تصنيف: ستة قرارات إلى «يحسمه الفريق» أو «يُرفع للجنة». 5) اختيار: كيف توثّق ما تقرر؟ |
| الخاتمة | اجتماع المعلم ينجح حين يخرج الحاضرون وهم يعرفون ما تغيّر، لا ما أُنجز |
| الوقت والنقاط | 12 دقيقة، 40 نقطة |

### 2.4 الأثر، الباب الأول: خريطة المدارس وما نأخذه منها

| | |
|---|---|
| المفتاح المقترح | `impact-frameworks-pick` |
| النوع | أداة |
| العنوان | أي إطار لأي أثر؟ |
| الدور والموقف | مسؤول قياس الأثر في برنامج حكومي، تصله خمسة طلبات تقرير من جهات مختلفة، ولكل جهة لغتها |
| ما يتمرن عليه | اختيار الإطار بحسب نوع الأثر وجمهور التقرير (مبدأ الباب) |
| الخطوات | 1) مطابقة: خمسة طلبات مع الإطار الأنسب (BRM، MSP، معايير DAC، SROI، OKR). 2) تصنيف: ثماني عبارات إلى «منفعة» أو «مخرج». 3) اختيار: لجنة المفاضلة تريد رقمًا واحدًا للمقارنة بين برنامجين، ماذا تقدّم وما تحذيرك؟ |
| الخاتمة | المؤشر وسيلة نحو قرار أفضل. الإطار الذي لا يخدم قرارًا زينة |
| الوقت والنقاط | 10 دقائق، 30 نقطة |
| تنبيه | يعتمد صياغة «جهة تقييم مستقلة» و«الجهة المموِّلة» من مسودة تسييق الأثر، فيُنفَّذ بعد حسم المصطلح |

| | |
|---|---|

| | |
|---|---|
| المفتاح المقترح | `manage-or-lead` |
| النوع | أداة |

### 2.7 القيادة، الباب الثالث: حلقة التسليم والتسلم

| | |
|---|---|
| المفتاح المقترح | `handover-loop` |
| النوع | موقف |
| العنوان | تسليم لا يسقط في الفجوة |
| الدور والموقف | مدير مشروع يسلّم منصة خدمات لإدارة التشغيل قبل نهاية العقد بشهر. المشغّل لم يحضر أي اجتماع سابق |
| ما يتمرن عليه | التسليم القيادي لا الشكلي، ومسؤولية المسلِّم ومسؤولية المتسلِّم كما في الباب |
| المؤشرات | جاهزية المشغّل، واستمرار الخدمة، وثقة المستفيد |
| الخطوات | 1) اختيار: متى تبدأ التسليم؟ 2) تصنيف: ثمانية بنود إلى «مسؤولية المسلِّم» أو «مسؤولية المتسلِّم». 3) ترتيب: خطوات حلقة التسليم والتسلم. 4) اختيار: المشغّل يوقّع المحضر دون تجربة، ماذا تفعل؟ 5) اختيار: عطل في الأسبوع الأول بعد التسليم، من يتحرك؟ |
| الخاتمة | التسليم ينتهي حين يعمل المتسلِّم وحده، لا حين يُوقَّع المحضر |
| الوقت والنقاط | 12 دقيقة، 40 نقطة |

## 3. ما تحتاج اللجنة أن تقرره

1. **اعتماد كل تصميم أو تعديله:** الموقف، وما يتمرن عليه المشارك، وهل يطابق ما يدرّسه الباب.
2. **الأمثلة السعودية:** الأدوار والمواقف هنا عامة («هيئة حكومية»، «برنامج تدريب وطني»). خبير المحتوى يقرر هل تبقى عامة أم تُسمّى قطاعات.
3. **المفاتيح الصحيحة:** كل خطوة تحتاج جوابها الصحيح وتعليل الخطأ. يكتبها الفريق بعد اعتماد التصميم ويراجعها الخبير، لأن الخطأ فيها يُقاس به المشارك.

## 4. ما بعد الاعتماد

1. يكتب الفريق مواصفة كل مختبر كاملة (نص الخطوات والخيارات والمفاتيح والتعليل) على نسق المختبرات القائمة.
2. تُراجَع المواصفات من خبير المحتوى، ثم تدخل بترحيل واحد ضمن إصدار محتوى، ويُختبر كل مختبر في المتصفح.
3. يُعاد تشغيل تقرير البوابات: المتوقع 14 من 27 بابًا لها مختبر بعد هذه السبعة، و18 من 18 بابًا تعليميًا بعد الأربعة المحجوبة.

## 5. حدود هذه المسودة

- تصاميم لا مواصفات: لا خيارات مكتوبة ولا مفاتيح. الوقت والنقاط تقدير على نسق القائم.
- أسماء الخطوات مأخوذة من عناوين الأبواب في `supabase/content/handbook/v3/`، ولم يُطابَق كل تصميم بمتن بابه سطرًا سطرًا. المطابقة جزء من كتابة المواصفة.
- لم يُجرَّب أي تصميم مع مشارك.
