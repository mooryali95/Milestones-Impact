# مهمة التنفيذ على الإنتاج v1

**التاريخ:** 2026-11-07 · **لمن:** زميل ينفذ (جلسة Claude Code) بتكليف المالك · **الحالة:** §4 و§5 نُفّذا في 2026-11-09: §4 كاملًا (92 من 92 ترحيلًا، انظر صف HANDOFF)، و§5 عبر CI (التشغيل 42653260503). المتبقي §6 Cloudflare و§7 للمالك

## 0. التكليف وحدوده

قال المالك في 2026-11-07: «ادمج وطبق الترحيلات جميعا واعتمد»، ثم: «فقط ابن ملف يوضح المطلوب والترحيلات واي شيء بحيث يقوم زميل لك بهذه النقاط جميعا».

**ما يأذن به هذا التكليف:**
- مسار الطوارئ في `RUNBOOK.md` §1 لتطبيق الترحيلات المعلقة كلها عبر Management API، لأن GitHub Actions موقوفة بالفوترة (عادت Actions في 2026-11-09).
- إقرار المالك لجدول تحويل تقييمات النماذج (D08)، ولتجميد SSPDF (D13).

**ما لا يأذن به وحده:**
- **تفعيل أداة القياس v5** (`20261102100100`): لا رجعة فيه بعد أول قياس مبدئي، والقرار D03 يشترط قبله توقيع لجنة المحتوى. قبل تطبيقه اسأل المالك سؤالًا واحدًا صريحًا، ولا تطبقه إلا بجوابه «نعم، فعّل v5».
- **نشر الدوال ودفع فرع `release`:** ممنوعان على الوكيل في `.claude/settings.json` منعًا مقصودًا. لا تلتف عليهما بأمر بديل ولا بواجهة أخرى. هما للمالك من جهازه، أو لـ CI بعد عودة Actions (§5).

**قواعد ثابتة:**
1. لا سر في أي ملف ولا في رسالة إيداع، ولا تطبع قيمة سر.
2. SQL الإنتاج عبر `scripts/db/apply-migration.mjs` وحده. والقراءة عبر أوامر select وحدها.
3. أول فشل يوقف السلسلة. لا تعدّل ترحيلًا مطبقًا ولا تتجاوز حارسًا. أبلغ المالك بالنص الكامل للخطأ.
4. لا تعطل التحقق من TLS، ولا تلغِ الوكيل.
5. العمل على فرع `claude/<اسمك>`، وكل تعديل في المستودع بطلب دمج بعد `npm run verify` أخضر على شجرة نظيفة (D16)، وبتذييل الإيداع وطلب الدمج المعتاد.
6. سجّل كل خطوة تنفذها في صف بـ `HANDOFF.md` (§7).

## 1. الوصول

اطلب من المالك مفتاح Supabase بأداة `request_credential`:
- **المضيف:** `api.supabase.com`
- **الترويسة:** `Authorization: Bearer`
- **مصدره:** لوحة Supabase، ثم Account، ثم Access Tokens.

المفتاح يُحقن في الطلبات عبر وكيل الشبكة، ولا تراه. والسكربتات تشترط وجود المتغير، فمرر قيمة وهمية يستبدلها الوكيل:

```bash
export SUPABASE_ACCESS_TOKEN=proxy-injected
```

إن رُفض الطلب برمز 401 أو 403 بعد حفظ المفتاح، انتظر دقيقة وأعد مرة واحدة.

## 3. بوابة النسخة الاحتياطية (D09)

لا ترحيل قبل نسخة ناجحة عمرها دون 24 ساعة. أحد ثلاثة يكفي:
1. نسخة Supabase يومية مكتملة يظهرها أمر backups أعلاه (خطة مدفوعة).
2. تشغيل المالك `scripts/ops/backup.sh` من جهازه (يحتاج `SUPABASE_DB_URL` ومفتاح التشفير، `RUNBOOK.md` §4).
3. إن تعذر الاثنان: صدّر قراءةً الجداول التي تكتب فيها الترحيلات (`leaders.model_submissions` معرّفًا وتقديرًا وحالة، و`leaders.questions` لأداتي `baseline-v5` و`post-v3`، و`leaders.instruments`، و`leaders.cohorts`) إلى مجلدك المؤقت خارج Git، واذكر في تقريرك أنها نسخة جزئية.

إن لم يتوفر أي منها فتوقف وأبلغ المالك.

## 4. الترحيلات بالترتيب

طبّق بـ:

```bash

```

يتخطى السكربت المسجل سلفًا، ويتحقق أن كل ترحيل سجّل نفسه، ويقف عند أول فشل. وبعد كل مجموعة نفذ تحققها قراءةً.

### 4.3 تحويل تقييمات النماذج (D08، أقره المالك)

قبله، عدّ التقييمات قراءةً واحفظ الناتج:

### 4.4 طبقتا أداة القياس (D03، على الأداتين غير المفعّلتين)

```bash
node scripts/db/apply-migration.mjs 20261105150000_leaders_v5_1_pre_activation 20261107190000_leaders_v5_2_balance
```

كلاهما يرفض إن بدأ قياس على الأداتين. والثاني يرفض إن خالف صف نص v5.1. إن رُفض لهذا السبب فتوقف، فهو انحراف لا يُتجاوز. تحقق:

```sql
select count(*) from leaders.questions q join leaders.instruments i on i.id = q.instrument_id
 where i.key in ('baseline-v5', 'post-v3') and (q.text_ar like '%مانح%' or q.options::text like '%مانح%' or q.competency_ar like '%مانح%');
select key, active from leaders.instruments where kind in ('baseline', 'post') order by kind, key;
```

المتوقع: صفر في الأول، و`baseline-v5` و`post-v3` غير مفعّلتين في الثاني.

## 6. ما يستطيعه الزميل في Cloudflare (بالمتغيرين `CLOUDFLARE_ACCOUNT_ID` و`CLOUDFLARE_API_TOKEN` في البيئة)

كلها تغيّر حساب المالك، فهي داخلة في تكليفه «النقاط جميعا»، ونفّذها بترتيبها:

1. **فرع إنتاج mi-home (قراءة):**

```bash
curl -s "https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID/pages/projects/mi-home" -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN"
```

المطلوب `production_branch` = `release`. إن كان `main` فأبلغ المالك، ولا تدمج أي تغيير في `home/` قبل تصحيحه.

2. **دلو النسخ وأقفاله:** أوامر `RUNBOOK.md` §4 الأربعة (`npx wrangler r2 bucket create mi-backups` ثم الأقفال الثلاثة).
3. **مراقب الحداثة:** `cd workers/backup-monitor && npx wrangler deploy`. سرّا البريد اختياريان، يضعهما المالك.
4. **إيقاف mi-sspdf** بعد 4.5 وبإذن المالك في الجلسة.
